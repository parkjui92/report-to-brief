**한국어** · [English](README.en.md)

긴 보고서를 1~8쪽짜리 짧은 문서로 줄여 주는 [Claude Code](https://claude.com/claude-code) 스킬입니다.

보고서를 주시면 결론을 맨 앞에 놓고, 그 문서만 읽어도 이해되도록 다시 쓰고, 중요한 숫자와 출처는 빼지 않은 채로 짧게 만들어 드립니다. 다 줄인 뒤에는 원본과 하나씩 대조해서 **무엇이 빠졌고 무엇이 뒤틀렸는지** 알려 드립니다.

## 요약과 브리프는 다릅니다

AI에게 그냥 "요약해줘"라고 하면 **요약**이 나옵니다. 브리프가 아닙니다. 둘은 생각보다 많이 다릅니다.

|  | 요약 | 브리프 |
|---|---|---|
| 순서 | 원본을 따라 처음부터 끝까지 | **결론이 맨 앞에** 옵니다 |
| 읽는 사람 | 원본을 이미 읽은 사람 | **원본을 안 읽은 사람** |
| 숫자 | 남을 때도, 빠질 때도 있음 | 반드시 **출처와 함께** 남깁니다 |
| 쓰임새 | 내용을 전달하려고 | **결정을 내리려고** |

순서를 바꾸는 일은 어렵지 않습니다. 진짜 어려운 건 **줄이는 과정에서 조용히 사고가 난다**는 점입니다. 중요한 숫자가 통째로 빠지고, 숫자는 남았는데 출처만 떨어져 나가고, 원문에 있던 "~한 경우에만"이라는 단서가 사라져 단정처럼 읽힙니다.

이런 사고는 브리프만 봐서는 보이지 않습니다. **원본을 아는 사람만 알아챌 수 있는데**, 브리프를 받아 읽는 사람은 정의상 원본을 안 읽은 사람입니다. 그래서 줄인 뒤에 원본과 다시 대조합니다.

→ [왜 만들었는지, 더 자세한 사용법](docs/why.md) · [전체 규격](SKILL.md)

## 어떤 순서로 진행되나요

```
원본 읽기 → 살릴 것 고르기 → ★확인 요청 → 짧게 쓰기 → 원본과 대조 → 브리프 + 대조 리포트
```

중간에 **한 번 멈춰 섭니다.** 원본을 다 읽고 나면 쓰기 전에 "이건 살리고 이건 버리겠습니다"를 먼저 보여 드립니다. 여기서 "방법론은 다 빼주세요"라고 하시면 그대로 반영합니다. **방향을 바꾸기에 가장 값싼 시점**입니다.

## 무엇을 확인하나요

짧게 만드는 일 자체는 어렵지 않습니다. **짧게 만들면서 거짓말을 하지 않는 것**이 어렵습니다. 그래서 다 줄이고 나면 원본과 대조하며 세 가지를 확인합니다.

- **원본에 정말 있는 말인가** — 브리프의 모든 문장을 원본에서 찾아봅니다. 없으면 🔴로 표시합니다. 줄이는 과정에서 없던 얘기가 생긴 것입니다. 원문의 "~한 경우에만"이라는 단서가 사라지지 않았는지도 함께 봅니다
- **이것만 읽어도 이해되는가** — 원본을 모르는 사람이 읽어도 말이 되는지 봅니다. 줄임말이 처음 나올 때 풀어 썼는지도 확인합니다
- **숫자가 출처를 데리고 왔는가** — 중요한 숫자에 출처가 붙어 있는지 봅니다. **원본에도 출처가 없던 숫자**는 이 스킬이 지어낸 게 아니므로 `⚠️[원문 출처부재]`로 따로 표시하고 확인을 요청합니다. 없는 출처를 만들어 채우지 않습니다

## 설치

```bash
mkdir -p ~/.claude/skills
cd ~/.claude/skills
git clone https://github.com/parkjui92/report-to-brief.git
```

번들 파일을 받는 방식이라면 [`report-to-brief.skill`](report-to-brief.skill)을 그대로 쓰시면 됩니다.

## 이렇게 쓰시면 됩니다

평소 말하듯 요청하시면 됩니다.

```
첨부한 보고서를 4쪽 정책브리프로. 청중은 국장급 의사결정자야    ← 분량·읽을 사람 지정
이 보고서 executive summary로. 결론·권고랑 리스크만            ← 어떤 문서인지 문장에서 알아듣습니다
방법론은 다 빼고 해외사례는 일본 건만 살려줘                    ← ★확인 요청 단계에서
첫 번째 확인 다시 해줘. 3번 문단이 원문보다 세게 나간 것 같아   ← 대조 결과가 미덥지 않을 때
```

분량은 `1p`/`2p`/`4p`/`8p` 또는 "원본의 1/N"로, 문서 유형은 `policy_brief`·`exec_summary`·`one_pager`·`issue_paper` 중에서, 읽을 사람은 의사결정자·실무자·일반 중에서 고르시면 됩니다. 아무것도 안 정하시면 `2p`·`policy_brief`·정책결정자로 진행합니다.

## 무엇이 남나요

브리프 본문(`.md`) 하나와, **원본과 대조한 결과 리포트**가 함께 남습니다. 얼마나 줄었는지, 무엇을 살렸는지, 위 세 가지 확인이 어떻게 나왔는지, 그리고 **일부러 뺀 것이 무엇인지**가 적혀 있습니다. 요청하시면 `.hwpx`나 `.docx`로도 만들어 드리고, **원본 파일은 절대 건드리지 않습니다**(항상 새 파일로 나갑니다).

리포트에서 **가장 먼저 보셔야 할 줄은 "일부러 뺀 것"**입니다. 세 가지가 전부 ✅여도 버린 것 중에 꼭 필요했던 게 있으면 그 브리프는 실패이고, 그 판단만큼은 사람이 해야 합니다.

## 알아두실 점

- **줄이기는 원본을 다시 쓰는 일입니다.** 원본에 없는 주장·숫자·출처를 만들어 내지 않습니다. 뒤집어 말하면 **원본이 약하면 브리프도 약합니다**
- **확인 작업을 스킬이 스스로 합니다.** 글 쓰는 쪽과 검사하는 쪽을 아예 다른 AI로 나눠 놓은 에이전트 팀 킷만큼 독립적이지는 않습니다. 오류를 줄여주긴 하지만 없애주지는 못합니다
- **출처가 진짜 있는지는 확인하지 않습니다.** 세 번째 확인은 브리프가 원본과 맞는지만 봅니다. 그 링크가 살아 있는지, 그 문헌에 정말 그 숫자가 있는지는 [fact-verify](https://github.com/parkjui92/fact-verify)가 할 일입니다
- `.hwp`/`.docx`/`.pdf` 파일을 바로 넣으시려면 [kordoc](https://github.com/chrisryugj/kordoc) 같은 추출 도구가 따로 필요합니다. 없으면 본문을 붙여넣어 주시면 그대로 진행됩니다
- 분량 환산은 국문 글자 수 기준이며, **정확한 쪽수는 한글·워드 파일로 변환한 뒤에야 알 수 있습니다**
